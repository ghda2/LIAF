## Entregue na sessão de 25/09/2026

### LIAF v0.3 (issues #012 parcial e #013 completa)

- Chamadas diretas sem `call`; `(call ...)` continua aceito, nenhum programa v0.2 quebrou.
- `(try expr)` e bloco `(on-err var ...)` em funções e rotas, com `E_UNHANDLED_RESULT`.
- Rotas declarativas `(route MÉTODO "/caminho" ...)`, com registro automático, parâmetro de path
  convertido e corpo JSON desserializado pelo wrapper.
- `E_ROUTE_PARAM`: `{nome}` no caminho exige parâmetro homônimo `int` ou `str`.
- Parâmetro de path passou a ser extraído **pelo índice no padrão**. A versão anterior lia sempre o
  último segmento, o que quebraria `/users/{id}/tasks`.
- `fs-rename` e `fs-write-atomic` (grava temporário + rename); `fs-write-file`, `fs-rename` e
  `fs-write-atomic` retornam `(result void str)`, eliminando o caminho `ok false`.
- `(list T)` serializa como array JSON nativo `[...]`.
- `E_UNUSED_EFFECT`: efeito declarado que o corpo nunca consome, direta ou transitivamente.
- Comando `liafc fmt` (`-w`, `-l`, `--drop-comments`), em `cmd/liafc/fmt.go`.
- `examples/task_api_v03.liaf` reescrito para usar rotas declarativas e `try`/`on-err`. A antiga
  `parse-id`, que fatiava o path com `(str-slice path 7 ...)`, deixou de existir.

**Quebra de compatibilidade registrada:** `(result void str)` invalidou `(if written ...)` em
`task_api.liaf` — código morto que testava um valor sempre `true`. Corrigido.
