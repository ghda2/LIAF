## 3. Análises e medições

### 3.1 LIAF comparada a outras linguagens

- **Diferenciais reais:** efeitos declarados e verificados (raro fora de Koka/Unison), forma canônica
  única, diagnósticos JSON para agentes, `Result` obrigatório, overflow que aborta, regra anti-injeção
  de SQL no tipo, baterias para serviços (HTTP, WebSocket, drivers de banco próprios em TCP puro,
  deploy). O vizinho mais próximo é **Ballerina**, não Python.
- **Não é linguagem geral ainda** (a própria SPEC §10.2 lista os requisitos): faltam closures,
  genéricos do usuário, tipos soma, funções privadas, testes escritos em LIAF, LSP.
- **Escopo:** o núcleo não é só web — dos ~96 builtins iniciais, só 14 eram web/WebSocket. A
  descrição honesta é *"linguagem para serviços e automações escritos por IA"*.

### 3.2 `workspace_ws` em LIAF contra Python

Escrito `examples/workspace_ws.py` (FastAPI + sqlite3), com comportamento idêntico: 16 verificações
das duas versões deram saída igual byte a byte, incluindo os defeitos da versão LIAF, mantidos de
propósito.

| Métrica | LIAF | Python |
|---|---|---|
| Linhas totais | 188 | 214 |
| Linhas de código | 157 | 161 |
| Bytes | 10.119 | 7.175 |
| **Tokens BPE (o200k)** | **2.660** | **1.623** (LIAF +64%) |
| Parênteses | 942 | 248 |

**Conclusão:** linhas enganam. O que o modelo paga é token, e aí a LIAF perde. O custo vem de
parênteses, anotações obrigatórias, repetição sem abstração (8 `on-err` iguais, 7 `get-db`) e JSON
montado à mão. Candidatos a cortar ~25–30%: `on-err` padrão no módulo, rota retornando struct direto,
estado global/pool, função de valor padrão.

### 3.5 Estimativa para um delivery multi-restaurante

Hipótese de ~100 leituras + ~12 escritas por pedido, requisições ~5× mais pesadas que o teste e
operação a 30–40% da capacidade:

| Servidor | Pico confortável | Por dia |
|---|---|---|
| VPS 2 vCPU | ~4 pedidos/s | ~60–80 mil pedidos |
| 8 núcleos | ~15 pedidos/s | ~250 mil pedidos |

É ordem de grandeza, não medição. **O limite real é a máquina única**: SQLite e o pub/sub do
WebSocket vivem num processo só, sem redundância.

## 4. Banco de dados: vazamento, correção e deadlock

**Causa raiz:** a LIAF não tem variável global, então o padrão natural é chamar `db-connect` em cada
rota. Cada chamada criava um pool novo, com um `sql.Open` que nunca era fechado (daí os 770 MB), e o
SQLite abria sem `busy_timeout`, o que fazia escritas concorrentes falharem com `SQLITE_BUSY`.

**Primeira correção (feita pelo Gabriel):** cache de pool por `driver + dsn` e PRAGMAs de WAL e
`busy_timeout`. Resolveu a carga, mas a revisão encontrou:

1. **Deadlock:** `DBConnect` travava `poolMu → c.mu` e `DBClose` travava `c.mu → poolMu`. Um teste com
   8 goroutines fazendo connect/close travou por mais de 20 s.
2. **Um `db-close` derrubava todos:** handles do mesmo DSN eram o mesmo objeto.
3. **PRAGMAs só na primeira conexão** do `*sql.DB`.

**Correção final** (`pkg/runtime/db.go`, `pkg/dbdrv/sqlite.go`):
- `dbPool` (compartilhado, com contagem de referências) separado de `DBConn` (handle por
  `db-connect`, com `closed` próprio). Ordem de lock sempre `poolsMu → mu`.
- Um dial por DSN de cada vez (`dialLock`). Os testes revelaram que 8 conexões simultâneas num
  SQLite recém-criado disputavam a troca para WAL e falhavam.
- PRAGMAs passadas no DSN (`_pragma=busy_timeout(5000)` etc.), reaplicadas pelo modernc em toda
  conexão; o valor definido pelo usuário no DSN prevalece.
- SPEC §19.3 documenta o pool compartilhado e a semântica do `db-close`.

## 5. Firewall do Windows e `LIAF_HOST`

Os testes que sobem servidores LIAF geravam um executável novo numa pasta temporária a cada rodada,
escutando em `":porta"` (todas as interfaces), e o firewall perguntava toda vez.

- `web.ListenAddr` usa `LIAF_HOST` (padrão: todas as interfaces, como antes). As portas 80/443 do

- Verificado: o processo aparece escutando em `127.0.0.1` e os testes não abrem mais janelas.
- Útil também em produção, atrás de Caddy/Nginx na mesma máquina.

## 6. Passo 1 — headers, query string e headers de resposta

```liaf
(request-header req "Authorization")                 -> (result str str)
(request-query req "status")                         -> (result str str)
(response-set-header res "Cache-Control" "no-store") -> Response
```

- Nomes seguem o que já existia (`request-body`, `map-set`), não `req-`/`res-`.
- Buscas retornam `(result str str)`, como `env-get` e `map-get`: um único padrão para "pode não
  existir". Header presente e vazio é `(ok "")`, diferente de ausente.
- `response-set-header` devolve uma resposta **nova** (testado que ramos não se contaminam).
- `Set-Cookie` acumula; os demais headers substituem. Definir `Content-Type` troca o JSON padrão.
- Nome inválido ou quebra de linha no valor → 500 sem vazar corpo nem headers (bloqueia injeção de
  header; o `net/http` corrigiria em silêncio).
- **WebSocket:** `(ws-route ... (params (req Request) (conn WSConn)) ...)` recebe o handshake. O
  navegador não manda `Authorization` em WebSocket, então o token vem na query e a recusa é
  `(ws-close conn 4401 ...)` em `on-open`.
- Exemplo e teste ponta a ponta: `examples/pedidos_api.liaf` (Bearer, isolamento por restaurante,
  filtro por query, CORS, cookie, painel WebSocket por restaurante).

## 7. Passo 2 — criptografia

```liaf
(sha256 texto "hex")                  (hmac-sha256 chave texto "base64url")   (secure-eq a b)
(base64url-encode s)                  (base64url-decode s) -> (result str str)
(random-token)          ;; rand       (password-hash s)    ;; rand            (password-verify s h)
```

- A codificação é literal, conferida na compilação (`E_UNKNOWN_ENCODING`), no mesmo padrão do driver
  de `db-connect`.
- Nenhum parâmetro de segurança fica com o programa: tamanho do token (32 bytes) e custo do hash
  (argon2id, 19 MiB, t=2, OWASP) são fixos.
- Hashes de senha simultâneos são limitados ao número de CPUs, para que uma rajada de logins não
  esgote a memória.
- Formato PHC com os parâmetros no próprio hash: endurecer o padrão depois não invalida senhas
  antigas (testado).
- Vetores oficiais nos testes: FIPS 180-2, RFC 4231 e o JWT de exemplo do jwt.io.
- `golang.org/x/crypto` e `modernc.org/sqlite` passaram a dependências diretas no `go.mod`.

## 8. Passo 3 — `std/` embutida e colisões

- `std/*.liaf` embutidos no `liafc` via `//go:embed` (`std/std.go`). `(import "std/x")` nunca lê o
  disco; a versão é sempre a do compilador. Funciona com o `liafc` rodando fora do repositório.
- Módulo inexistente → `E_IMPORT_NOT_FOUND` **listando os disponíveis**. Módulo da std não importa
  arquivo relativo (`E_STD_RELATIVE_IMPORT`). Caminhos como `std/../x` são recusados. Pasta local
  chamada `std` continua acessível com `"./std/..."`.
- `E_DUPLICATE_DECL`: nome declarado em dois arquivos, com os dois locais na mensagem; se um lado é
  da std, a mensagem diz que o nome pertence a ela.
- `E_DUPLICATE_ROUTE`: rota repetida, **inclusive no mesmo arquivo** — antes ninguém pegava, e o
  `ServeMux` do Go dava panic na subida. `ws-route` ocupa o `GET` do seu caminho.
- `generateExample` (testes do codegen) e a suíte de conformidade passaram a usar o loader, então
  exemplos e casos podem fazer `import`.

## 9. Passo 4 — bibliotecas em LIAF

| Módulo | API | Garantias |
|---|---|---|
| `std/auth` | `auth-bearer-token` | Erro para header ausente, esquema `Basic` ou token vazio |

## 10. Palavras reservadas como nome de campo

`sub` é o builtin de subtração e também o claim padrão do JWT. `(struct Claims (fields (sub str)))`
não compilava, então JWT emitido por outro sistema não se decodificava.

- `token.IsName` aceita identificador ou palavra reservada em posição de nome de campo (exceto
  `true`/`false`), na declaração e no segundo argumento de `field`.
- `(sub a b)` continua sendo subtração. O `liafc fmt` imprime uma forma que é lida de volta igual
  (testado).

## 11. Passo 5 — cliente HTTP

```liaf
(http-fetch "POST" url (list "Authorization: Bearer x") corpo) -> (result HttpReply str)  ;; net
(reply-status r) -> int   (reply-body r) -> str   (reply-header r "Nome") -> (result str str)
```

- `http-get`/`http-post` **já existem**, como a forma v0.2 de registrar rotas; por isso o nome
  `http-fetch`. O AI_GUIDE avisa explicitamente.
- Semântica do `fetch` do JavaScript: `err` só sem resposta; um 422 é `ok` com status.
- Método literal conferido na compilação (`E_UNKNOWN_METHOD`); método de variável conferido na execução.
- Timeout de 30 s, corpo limitado a 10 MiB e obrigatoriamente UTF-8, headers validados, corpo sem
  `Content-Type` enviado como JSON.
- Mensagens de erro trazem método e host, **nunca a URL** (tokens na query não vão para log).
- Exemplo e teste ponta a ponta: `examples/cobranca_pix.liaf` contra um provedor falso — Bearer,
  `Idempotency-Key` com `random-token`, JSON e tratamento do 422.

## 12. O que percebi

1. **A falta de variável global molda todo programa.** Ela causou o padrão `get-db` por requisição e,
   com ele, o vazamento. A correção ficou no runtime (pool compartilhado), mas a pressão continua: é
   uma decisão de design a revisitar junto com a economia de tokens.
2. **Convenções consistentes valem mais que nomes curtos para IA.** Toda busca retorna `result`; todo
   argumento que escolhe uma variante (driver, codificação, método) é literal conferido na
   compilação; toda resposta é valor imutável.
3. **O sistema de efeitos funciona na prática.** Ele pegou meu próprio erro (`env` declarado e não
   usado no `pedidos_api`) e obriga `rand`/`clock`/`net` a aparecerem na assinatura.
4. **Segurança por padrão é barata quando é fixa.** Nenhum dos builtins de crypto ou do cliente HTTP
   aceita parâmetro de segurança; o caminho fácil é o seguro.
5. **Testes ponta a ponta acharam o que os unitários não achariam:** a disputa de WAL no SQLite
   recém-criado, a rota duplicada que derrubaria o binário, o `sub` do JWT.
6. **A tese central ainda não tem evidência.** Tudo o que foi feito melhora a LIAF para *rodar*. A
   promessa é sobre *escrever*, e o único dado (Gemini Flash, 0 de 3, dados apagados) é anterior a
   estas mudanças.

### Armadilhas encontradas

- **Python no Windows grava CRLF** ao editar arquivos: deixou o `parser.go` inteiro fora do `gofmt`.
  Use `newline=""` ao abrir, ou verifique com `grep -l $'\r'`.
- **PowerShell 5.1 remove aspas duplas** ao passar argumentos a programas nativos (`'{"a":1}'` chega
  como `{a:1}`): escape como `'{\"a\":1}'`.
- **`localhost` no PowerShell tenta IPv6 primeiro**; o uvicorn escuta só em IPv4. Use `127.0.0.1`.
- **`liafc run`/`build` fora do repositório falham**: o código gerado importa `liaf/pkg/runtime` e
  precisa do `go.mod` do projeto.
- **Nenhum exemplo está na forma canônica** do `liafc fmt`, porque o formatador apaga comentários.

### Documentação desatualizada encontrada

- `docs/ARCHITECTURE.md` ainda descreve tags de fechamento `[fn x ... /fn x]`; a sintaxe atual é
  S-expression pura.
- O `sqlite` era aceito pelo checker, mas não aparecia na lista de drivers da SPEC (corrigido).

## 13. Limitações e pendências

escritos em LIAF, tipo de bytes, comentários preservados pelo `fmt`.

`OPTIONS` por caminho.

**Toolchain:** runtime embutido no `liafc` (compilar sem o repositório), LSP, backend C incompleto.

**Operação:** SQLite + pub/sub em memória prendem a aplicação a uma instância.
